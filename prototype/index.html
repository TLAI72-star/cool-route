How CoolRoute v1 works

Deterministic, explainable baseline (per the system architecture guide): sun position → street-canyon shade → edge heat cost → three routing objectives.

Edge heat cost

EdgeHeatCost = length × (w1·HeatIndex + w2·SunExposure + w3·LowWind + w4·SurfaceHeatProxy − w5·CoolingAccess)

w1 = 0.35, w2 = 0.30, w3 = 0.10, w4 = 0.15, w5 = 0.10 — initial domain weights, to be calibrated with pilot survey data. Scores are normalised 0–100 and used only for relative route comparison.

Routing (real streets)

Route candidates come from an OSRM foot-profile demo server (routing.openstreetmap.de, OpenStreetMap data, no API key): the direct query plus its alternatives and a few shade-corridor waypoint variants are deduplicated, then each candidate is scored thermally per ~30 m segment. Each segment's street name (from the API) maps to a Central canyon table (width, podium height, trees); names like “Central-Mid-Levels Escalator” are auto-detected as covered.

Route objectives

  • Fastest — minimise the API's walking time.
  • Coolest — minimise cumulative heat cost.
  • Balanced — time × (1 + λ·heat), λ grows with your heat-sensitivity setting.

Shade model

NOAA solar position for the departure time; the sunward-side building casts a shadow band H / tan(elevation) across the street width; tree canopy and covered walkways (escalator, elevated walkway) add shade on top.

Data sources & licences (prototype → production path)

  • Routing: OSRM foot demo server, OSM data (ODbL, fair-use demo) → self-hosted Valhalla or LandsD 3D Pedestrian Route Search API. Google Directions could also be plugged in, but requires a paid API key.
  • Weather: Open-Meteo (free non-commercial tier) → HKO / DATA.GOV.HK.
  • Buildings / trees: Central canyon table (demo values) → LandsD/CSDI building heights + tree datasets.
  • Basemap: CARTO Voyager (© OpenStreetMap contributors, © CARTO).
  • Thermal model upgrade path: pvlib + pybdshadow + pythermalcomfort (MRT / PET / UTCI).

Designed failure modes

Routing API down → built-in simulated pilot network with an on-screen notice. Weather API down → stale-data warning + cached snapshot. No shadow data → sun-exposure proxy. Low model confidence → wording downgraded to “lower estimated heat exposure”. Rate limits → cache / self-host.
